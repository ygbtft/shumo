## 3. 唯一保留的实施建议：Q3历史阴性距离支配裁剪

**状态：新临时原型，尚未接入主候选。优先级：中。成本：约半天至一天实现与针对性验证；收益较小，不列高优先级大改。**

### (a) 具体位置

- `policies.py:23`—`:40`：收到 `no_signal` 不更新区域。
- `geometry.py:79`—`:89`：只处理成功示向角及1500米外包。
- `joint_task_policy.py:34`—`:41`：`_attempted` 只存位置用于共享去重，没有把真实阴性与推断标签分开用于Q3位置推理。
- `completion_sensing_policy.py:110`—`:145`：随后用当前区域选点、试探清除或有限兜底，是收紧区域发挥时间收益的位置。
- 临时实现：证据包 `probe.py` 中 `OmniNegative`，叠在原 CoupledCompletionPolicy 之前，不改变清除门或主动轮数。

### (b) 为什么现在不够好：可证的遗漏信息

Q3同一静止全向源位置为g、未知固定半径ρ。实际在a收到方向，在q收到无信号，则

\[
\|g-q\|>\rho\ge\|g-a\|,
\quad 2(q-a)^Tg<q^Tq-a^Ta.
\]

这是**单个半平面**，无需知道ρ，无需估计源位置或误差概率。它与“no_signal排除1000米圆盘”不同，避免非凸差集；也不同于 `negative_hull_policy.py:68` 要求两个成功点的阴影法。

具体反例：原点q=(0,0)阴性，随后环站a=(1140,0)测到180°方向。仅该方向与最大半径允许很长的一段候选，约从x=−360到1140；上述历史阴性立即给出 **x≥570** 的保守外包。真源g=(1100,0)、ρ=1000完全合法：q距源1100收不到，a距源40收得到。主路径目前没有使用这条半平面。实际复核300局中142局触发裁剪，共506次切割，故不是只有纸面例子。

### (c) 改法概要

每频道缓存**真实被接受的** `no_signal` 位置，包括该频道首次被发现之前的站扫；在拿到首个成功锚点后，及以后增加阴性/成功锚点时，交上相应半平面。试验使用当前所有成功锚点；每次区域改变清掉 `_circles[ch]` 缓存。核心为：

```python
# q: actual accepted no_signal; a: actual successful bearing position
n = 2 * (q - a)
b = float(q @ q - a @ a) + 1e-4  # outward slack in squared-distance units
candidate = clip(poly, n, b)     # existing clip adds outward distance tolerance
```

不要把 `certified_no_reception` 当服务器阴性写入此记录；本原型仅记 `result == 'no_signal'`。生产实现宜在已有公开反馈更新点完成交集，保留旧区域应对不一致，并去重/增量维护历史约束；原型不一致即报错，没有默默删除频道。**这些工程整理尚未实施，不能拿它们的假想额外节省计入结果。**

### (e) 第二轮反证、风险和不变量

- **真的保证整局更快吗？不保证。** 300局有25局变慢；最差种子202610289总时间+390.202秒，最好202610317为−588.381秒。区域变小会改变测点、共享与站序；面积先验也可能选到更差动作。只声称样本平均收益。
- **会破坏包含性吗？** 精确算术下上述不等式保证不删真源；300局记录24990次区域赋值，最小真源余量0.000951米，无认证清除失败。浮点余量仍需按距离单位归一化审查、覆盖共点/近共点与点线退化，不声称有限样本是全输入证明。
- **能用到Q4吗？不能。** g=(0,0)、朝东、a=(100,0)成功、q=(−1,0)阴性时，q实际更靠近源；阴性来自背向，距离支配不成立。必须Q3限定，不能通过Q4 `mixed` 模糊复用。
- **能用于未知源排尽吗？不能。** 没有成功锚点的频道不能应用此推导；仍须未知频道完整覆盖、16上限逻辑、共享去递归、3次主动预算和有限光学兜底。收紧后MEC只能作真实包含圆使用，清除精度仍是20米。
- **边界怎么办？** 保留闭半平面并外放，绝不为多省一点时间改成向内容差；通信错误/拒绝动作绝不是阴性。例中仅裁剪到x≥570，未声称得到精确非凸后验。

### (f) 实施决策

值得作为单独Q3变更推进；合并前重点补“阴性先于发现、成功先于阴性、多锚点、距离相等边界、重复坐标、退化区域、缓存失效”验证及坏尾部回放。继续保持50米门。此次仅提交评审证据，没有修改生产代码。

## 4. 路线目标与真实时间：缺项成立，但简单修法未通过

### 4.1 具体缺项和反例

`adaptive_routes.py:10`—`:31`、`joint_task_policy.py:82`—`:93`、`interleaved_policy.py:63`—`:70`只比较代理点距离；`coupled_dispatch_policy.py:113` 的base直接转父类。它们没有模拟发现后增加源任务、测向后区域缩小、共享改变可用信息、源任务实际出口、频道状态以及16上限后的终止。

在一个冻结状态模型里，当前在0，扫描站在10米，未精确源的服务出口在30米：扫描→服务走30米，服务→扫描走50米，多走4秒；但服务先完成能免掉该源在扫描站的5秒RF，可能再免1秒切频，故只比路长可以选错。**这是目标缺项的代数反例，不是本次实跑轨迹**；真实扫描可能帮源定位，免RF也可能同时损失信息，这恰是不能直接给“先清源奖励”的原因。

### 4.3 后续研究应满足什么，而不是马上改什么

若继续做路线优化，评分应是**候选首任务执行到合法交还点的费用＋条件于公开反馈的剩余虚拟时间估计**：

\[
\hat J(a\mid H)=E_{W\sim\pi(\cdot\mid H)}
 [L_a/5+5M_a+S_a+5C_{s,a}+3C_{f,a}+\hat V(H')].
\]

W只能是与公开历史一致的内部假设世界，不能是mock真值；比较候选时共用样本。Q4必须模拟完整成功/双阴性包后再估出口和后验；未知源发现/空频道与16上限要反映在尾部项，不用 `discovery_priority_policy.py:73`—`:79` 的有限样本耗尽充当停止证书。源精确免扫要避免重复奖励。已有 `completion_sensing_policy.py:73` 的协方差半径只作排序，也不能直接当“还需几次RF”的真概率。

**状态：仅研究设计，收益未知，不保留为本轮实施建议。** 如推进，优先级中、成本高（至少数天的后验/回放与独立验证）；先在相同公开状态的候选首动作上测排序与实际后续T的相关性，超过当前两种失败代理后再跑闭环。风险是先验失真、Q4包出口偏差、CPU挤占现实期限；不应因虚拟时间不计计算就无限加大rollout。现有覆盖、包原子性、生命周期预算及有限兜底全部必须保留。

\[

切频首项对两侧同频道相同，省略不影响这个包内比较。近侧不是普遍期望最优：若远侧多走2秒，但成功率多0.5，两点间80米，则少做第二次探测的期望价值为0.5×21=10.5秒，足以抵消；这是**假设概率已知**时的算式，不是当前真实概率。

测得初筛−1.7850、60局−1.4892，但最终300局 **+0.5044秒/源，区间[−1.688,+3.030]**，138局变慢，最差+2112.81秒/局；聚集组+5.6322秒/源，失败清除236→251。原因可能包括先验、后验质量、成功出口与后续调度失配；本实验不能将因果归于唯一一项。

改点顺序本身保留原探点、双阴性完整性、预算和有限兜底，300局12496次区域记录均含真源；但**正确性保留不等于性能提升**。状态：原型已测淘汰；实施优先级低，编码成本低，可靠建模成本高。不得用“再加更多角度”凑出未经测量的收益。

### 5.2 合并包内共享、减少切频：有小信号，仍不推荐替换

位置：`efficient_joint_policy.py:32`—`:41` 每次主RF之后立即共享；`interleaved_policy.py:97`—`:138` 一个包可有两次主RF。同一源双探点之间插入别的频道，确实可能产生切出去再切回的费用。

原型 `PacketShare` 暂停整个 `source_packet` 中的可选共享，包结束时仅在最后真实位置调用一次 `share_at`。这是**减少并改变共享位置的消融**，不是无损重新排序；双阴性证据和主RF仍完整，10轮及中断上限不动。

最终300局：平均−0.1505秒/源，但区间[−0.472,+0.241]跨零；共享4096→4010、RF83274→83205、切频76660→76399，失败清除236→241，移动略增。19局变慢、最差+586.63秒/局。已有成功信息可能在第一点顺路获得，推到第二点会失去机会；少261次切频共261秒，不能抹掉其他联动成本。状态：原型已测、证据不足；低优先级，低编码成本，不保留为实施建议。

### 5.3 切频100—145次不等于有100—145秒可省

本轮300局Q3基线平均114.67次切频/局、122.18次RF/局，量级与用户提供的官方描述相容，仍是不同数据来源。

对同站必须测的k个不同频道，若当前频道在集合内，最少k−1次切频，否则最少k次。`joint_task_policy.py:113`—`:116`、`interleaved_policy.py:180`—`:183` 已把当前频道放首位，常规无跳扫/无额外动作时达到该局部下界。频率数值相邻没有额外折扣。

可选的“把预测下一源频道留到站扫最后”在固定测量集合、反馈不改动作、站扫出口不变、下一动作频道已知且允许作为末项时，可省至多一次边界切频；当前频道唯一免切的情况还可能必须先测它，尾项优化没有免费余地。全局效果会受near即时清除、跳扫、区域更新、插入顺序影响。**状态：仅想法、未测；理论上是每个合格批次0或1秒，而不是把全局S大幅砍掉。** 位置同上，优先级低、成本中（需先固定动作集合并回放验证）；不以此提出生产改动。

## 6. 停止准则：当前站集不能靠直接删站安全提早结束

位置：`efficient_joint_policy.py:15`、`interleaved_policy.py:51`、`joint_task_policy.py:128`—`:134`、`interleaved_policy.py:200`—`:208`。现有16上限与未知频道完整站扫的停止逻辑已经实现。

本次额外搜索并逐项核验了**每个站的独占可见源见证**：Q3有7/7，Q4有21/21。见证g在1800米域内、半径取合法最小1000米；Q4附具体朝向，使全部站中仅该站能收到。按范围/朝向外放1e−5容差再核查，其他站仍不可见。文件见证据包 `coverage-witness.json`；脚本以91个径向层、360个位置角、Q4的72个朝向寻找反例，随后独立标量复核每个保存的见证。结论来自**找到的具体反例**，不是“采样没发现空洞所以覆盖成立”。

例如Q3原点站的见证是g=(0,0)、ρ=1000；六个环站均距1140。Q4路线索引0的一个见证是g≈(19.9725906951,1.0467191249)、朝向185°、ρ=1000。

这说明当前原始站集删去任何单站，都存在可漏掉的合法未知源。对于未达16源上限且某频道尚未出现、该频道只在其余覆盖站扫过的历史，不能仅凭“已扫很多站/剩下一个站/连续无信号”宣称排尽。见证也可嵌入尚有公共源数容量的其他频道场景。

边界：**不证明所有自适应额外测量都不可能更早形成覆盖证书，也不证明站数全局最少。** 若未来对未知频道额外测过定位点，确可尝试使用真实测点集合重新做连续覆盖认证；但当前 `share_at` 只测已知源，不能将别的频道成功测点算给未知频道。主动补未知频道每项至少5秒及切频，还可能不如扫完原站。

“未知数最优停止”若允许漏源，应另有漏源代价和可信先验；本轮硬约束不允许以这个目标替换全清正确性。因此：不推荐统计式早停或按有限假设耗尽停止（`discovery_priority_policy.py:76`—`:88`）；不把角边界保守余量收紧作为优化。优先级低，重新建立动态连续覆盖证书成本高，未测得可兑现收益。
