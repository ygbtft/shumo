# Q3 全局发现—定位—清除路径研究：原型与否决记录

本轮没有达到 150 s/源。训练阶段选定的 `lookahead_full_path` 在独立验证中为 **244.2588 s/源**，基线为 **245.2669 s/源**，配对差 **-1.0081 s/源**（95% 区间 [-2.2095, +0.2477]）。验证中 189/420 局变慢，最差增加 752.29 秒，最大相对退化 22.23%。两者均 420/420 全清。表观改善约 0.41%，但区间跨零，尚不能确认稳定提速。

所有新候选中验证均值最低的是 `lookahead_full_path`：**244.2588 s/源**。这是完整表内的描述性最小值，不是在验证集上重新选参后得到的收益。本轮**否决替换主候选**：收益远不足以支持 150，且存在明显逐局回退。主工厂、默认入口和布局未修改。

## 1. 目标、数据与边界

目标使用源加权口径：`τ = Σ整局虚拟秒 / Σ真实源数`，不平均各局的 `T/n`。分母只在执行结束后由评分器读取。每个候选验证 420 局，共 5460 个真实源。

接受用户已确证的 117.5 s/源混合场下界，以及 10—15 源分别约 181.8、163、147.3、134.1、122.7、112.9 的单局地板。本轮不重新论证或推翻它们。150 未被该下界排除；本实验失败也不构成不可达证明。所有低源数局仍全清并完成原七站扫描。

所有数值来自本轮新生成的本地 mock 场景、反馈与计分。没有将任何内存恢复数据、既有正式统计或官方轨迹作为实验输入、先验、校准数据或结论证据；没有进入 `jlog-research/` 读取文件。初始阅读用户指定的既有报告只用于了解已经否决的方向，本报告不复用其中的正式局数据。

运行器只实例化 `mock.protocol.Protocol` 的内存 transport，不创建 HTTP transport、不访问官方模拟器、不触发正式测试。指定解释器为 `/Users/flower/math/2026/B题/mock/.venv/bin/python`。实际计费逐条重算：`L/5 + 5M + S + 5Cs + 3Cf`。

## 2. 原型针对什么结构

现有主策略已经将未访站与未清源 MEC 中心进行最近邻＋2-opt 排序，每次执行首任务，并通常一次完成该源。因此把冻结点集改成更精确 TSP，不能代表信息随移动变化的实际过程。本轮没有重做 MILP，也没有给旧路线评分增加测量、切频费用或重扫四参数。

代码见 [prototypes.py](prototypes.py)。全部候选只在该文件的 `REGISTRY` 注册。

### A. 推进式站序与路径补测

`sweep` 先冻结原七站从原点出发的完整开放路线，再将已知源按最小插入距离放入路线。后续保持站点相对次序，源服务可以插入站间。这是对“不回头站序”思路的对照，使用了仓库已有的源插入思想，不宣称它本身是新算法。

`sweep_path` 还改变实际补测点：候选包含原 completion 点、当前点通向源 MEC 中心及后续任务位置的 1/4、1/2、3/4 点，以及源中心在线段上的投影点。对可行多边形的面积先验取五个确定性分位样本，在 0、±1.01° 预测误差下裁剪临时区域，比较“到补测点→预测清除中心→后续任务”的路程，加 `2 max(0, 预测MEC半径−20)` 的剩余定位路程代理。

该评分是有限采样启发式，不是最坏情形界、真实源分布或贝叶斯最优决策；实际清除只遵循原反馈与判据。原 completion 点保留为可选后备，但代理值更优不保证整局时间更优。

### B. 会预测站点信息的三步前瞻

`lookahead` 对每一个首任务分支，用宽度 4 的束搜索看未来 3 个任务。巡站动作会对**保证可接收**的已知源，在局部副本中按预测中心方向收紧区域；服务动作计原 completion 入口及到预测清除中心的行程。每步排序包含剩余路线，实际执行只使用真实反馈。

初版末端只使用剩余 MEC 中心路线，存在“将困难定位推到三步之外，终端又不计其服务成本”的低估。训练中识别后，新增 `lookahead_full`：将末端整条启发式路线继续推演完，逐一计入定位入口、清除出口以及站点观测后的区域变化。它仍不是所有未知发现的场景树，也不是全局最优解。

`lookahead_path` 和 `lookahead_full_path` 分别叠加 A 中的实际路径补测。后者是训练均值最好的新候选，**验证前预选**，训练仅减少 0.1322 s/源，训练区间跨零，没有把这当作突破。

### C. 固定行程线段上的自然补测

`corridor` 保留原调度，但在已选巡站路段的 20%、40%、60%、80% 点，为已知且尚粗糙的源预测一次观测。仅在保证接收，且样本的所有预测半径≤50 m、平均半径小于旧半径40%时执行。按照线段参数递增行进，关闭该额外动作的机会共享，随后继续到原定站点。每源至多增加两次这样的 RF。

这些门限只筛选是否值得花真实 5 秒检测及可能的切频，不改变真实清除半径。50 m 只是已有试探门。预测失准仍回到原策略。

开发中的第一版本也曾附着到源服务入口，但源完成函数会在新反馈后重算入口，无法保证原定终点。因此最终版只用于终点确定的巡站路段，旧版保留于 `prototypes-stage2.py` 和 `corridor-training/`，不把旧版混入最终验证。`corridor_lookahead` 则与三步前瞻组合。

## 3. 没有改变的正确性约束

- 七站坐标、站点访问义务和未知频道扫描保持原样。只在发现公开上限 16 个源时使用既有提前终止逻辑。
- 实际区域仍由原 `update_region`、Q3 真阴性距离支配及真实反馈更新；预测区域仅存在局部副本。合同检查确认规划不改写实际区域。
- 角包络仍为 ±1.01°；认证清除门仍为 `20−1e−5` m，并复用原最近可清位置。一次 50 m 试探不等于认证，失败仍继续处理。
- 每次源完成保留最多三轮主 RF、原单次试探、原共享及有限光学覆盖兜底。巡站线段补测另外受每源两次的有限预算约束。
- 调度中没有丢弃已发现源。每次 source 任务沿用整源有限完成；所有未发现频道最终取得原证书要求的观测。

规划器只接收 Client 公共位置/频道、已接受观测、可行区域、已清频道和公开常量，不导入 mock、不读取真坐标、真实半径、朝向、隐藏源数或种子。仿真真值仅留在运行器；包含性检查在 `policy.run()` 返回后进行，不反馈给策略。

验证 **3780/3780 次执行全清**，区域赋值检查 140093 次，误排真源 0 次；低于16源但未走满七站的局数 0。最大逐局账本残差 0.00000559 秒，符合逐段微秒舍入。既有阴性合同测试 `24 passed, 8 subtests passed`。这些是有限验证及继承保证，不把抽样全清率当成对所有误差场的新证明。

## 4. 训练冻结与独立验证

初筛：`202695000—202695006`，7 局；训练：`202696000—202696209`，210 局。所有开发与修正只使用这组训练种子。第一阶段 4 候选、第二阶段巡站补测开发版、第三阶段终点修正与完整尾部估价均留存原始日志。

冻结后独立验证：`202697000—202697419`，420 局；八个最终实验候选和同场基线全部进入验证，没有根据验证结果修改策略。每完整 105 局覆盖 7 个源数（10—16）×3 种空间分布（uniform、edge、clustered）×5 种误差场（iid、smooth、恒+1°、恒−1°、空间±1°）；相邻 105 局块交替用均匀半径与固定1000 m，Q3 全向。验证共四块，每源数60局。这是预设的本地合成混合场，不代表官方分布。

误差绑定位置、频道及场景种子，候选改变调用次序不会重抽同点噪声。冻结清单见 [frozen-validation.json](frozen-validation.json)，验证加载 `snapshot/B`、`snapshot/mock` 源码快照；当前主目录不被实验覆写。7 个训练基线种子经快照重放，虚拟时间逐位一致。

## 6. 剩余差距主要在哪里

基线 τ=245.267，其中移动 184.491 s/源（75.22%），动作 60.776 s/源。仅空频道测量已占 **18.652 s/源**；全部切频占 8.744 s/源。

为了不把“去源附近”都误记成定位浪费，对每条实际轨迹按固定次序作三个三角不等式短接：①删去非巡站 RF，但保留全部清除点；②再删去失败清除点；③再删去成功清除点，只留实际巡站序列。按此顺序得到四项可加分解：

|基线实际路程组成|m/源|s/源|
|---|---:|---:|
|实际巡站次序的折线路径|520.106|104.021|
|成功清除点插入后的增加|351.310|70.262|
|失败清除点的额外折线|1.299|0.260|
|非巡站 RF 测点的额外折线|49.740|9.948|

这是对固定实际位置和次序的**诊断**，不是可执行候选，也不是任务下界。尤其成功清除插入项同时包括去离站源的必需行程和可优化绕行，不能全部称为浪费。删除 RF 后原清除位置可能无法在线获知，所以没有把短接结果冒充可实现 τ。

然而它明确指出：在保留现有扫描和清除位置/次序的条件下，就算专门定位测点完全免费消失，路程收益也只有 **9.948 s/源**。距150仍有 **95.267 s/源**。本轮主要瓶颈是巡站与实际清除服务位置之间的衔接，而不是大量多做几次原地 RF；沿途补测最终共执行 110 次，107 次使对应源达到预测试探门或已清，作用机会本身就有限。

折返诊断忽略≤1 m的移动，以相邻保留移动向量夹角>120°计数；基线平均 5.969 次，三步前瞻平均 5.676 次。该计数不是行程指标：减少折返的同时可能多走外围站、推迟清源，导致已知频道留到更多站重复检测。初版前瞻的移动τ变化 -1.754，动作τ变化 +3.709，需合并评判。

预选候选把定位测点额外路程从 9.948 降至 6.646 s/源，但成功清除插入项反而增加 0.716 s/源；整体移动仅减少 2.972 s/源。同时全部 RF 从 50789 增至 52635 次，动作增加 1.964 s/源，最终只剩 1.008 s/源的表观均值差。巡站线段补测单独候选虽在验证中减少0.1973 s/源，但训练反而增加0.0731 s/源，不能称为跨阶段稳定复现。

完整尾部估价修复了“将定位成本移出视野”的已知建模缺陷，但仍没有预测未知频道何时被发现，也没有把每个未来误差反馈及后续清除出口组成完整场景树。路线更精确的代理仍可能给出更差的实际清除/巡站顺序。这是本轮实现的限制，不是对所有全局一体化规划的否定。

## 7. 最差逐局退化及处置

训练预选候选最差增加秒数的验证局：种子 `202697151`，uniform/adversarial/positive，14 源。基线 3384.271 秒、13001.4 m、7 站、118 次检测；候选 4136.556 秒、16072.8 m、7 站、141 次检测。两者全清。

**否决及原因：**推进式固定站序不能适应未知发现，束搜索虽纳入局部信息变化，仍存在未来发现与真实服务出口的预测偏差；自然测点机会不足以抵消整局服务路线成本。可保留原型作为后续研究基础，但本轮没有足够收益和逐局稳定性支持替换默认，也没有接近150。
