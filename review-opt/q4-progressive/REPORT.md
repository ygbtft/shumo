# Q4 定位/清除绕行与全局路径：结构原型及独立验证

**结论：获得小幅可复现收益，没有取得结构性突破。** 独立 420 局混合场上，最好的已冻结实验候选 `asymmetric` 将源加权均值从 **467.759 降到 464.304 s/源**，减少 **3.455 s/源（0.739%）**。420/420 局全清，303 局更快、117 局更慢，最差整局增加 2285.255 s（52.50%）。不能称为逐局改进，也没有到达 449 以下的证据。

保留 `asymmetric`、`flow_rollout` 作为有平均收益的研究候选；**否决将本轮结果称为“大幅压低 τ 的突破”，不替换主候选默认。** `flow_forecast` 和 `history` 的独立验证区间跨零，否决其稳定收益主张。这里没有仅因个别局变慢就把已复现的均值收益抹掉，但逐局回退必须一起审阅。

所有新文件都在本目录。生产 Python 与布局文件哈希未变。只读取既有 formal 请求归档，整局实验仅使用本地 `mock.protocol.Protocol` 内存 transport；没有访问官方模拟器、没有正式测试、没有使用 `jlog-research/` 数据。解释器为 `/Users/flower/math/2026/B题/mock/.venv/bin/python`。

## 2. 实施方案与原型

实现文件：[prototypes.py](prototypes.py)。候选只登记在该实验文件的 `EXPERIMENTS` 中，通过 [experiment.py](experiment.py) 构造单个实例。`bounded_candidates.SPECS`、`range_grid21_29` 默认及其布局保持原样。

### A. 推进服务窗口与全局观测预测

- `window`：保持完整扫描骨架，给每个已知源计算整条剩余路线上的最小插入绕行；在即将越过其最近服务窗口时启用原定位包，提前阶段等待站点真实观测。
- `ready`：只将20 m认证完成的源插入巡访骨架，其余留给后续观测；这是用于证伪“尽量等免费站点定位”的对照。
- `flow_forecast`：每次基线选中待定位源时，将当前定位包与后面三个巡访候选站的真实测量机会比较。在公共外包生成的假设源位置/朝向下预测正反馈或失收，再重算**全部剩余站点＋源任务**的开放路线。假设失收只有完整探测对才能切割；单站失收不缩区域。

### B. 沿路补测候选＋三轮完整定位预测

`corridor` 从当前点、公共源圆心及后继任务构成的行进线生成补测交点，并允许复用最近四个实际正反馈锚点。纵向位置由行进几何给出；每侧仍保持1.02°—30°安全探测斜率。它增加的是路线相关候选，未再次扫描冷却、固定横宽、固定角上限等旧参数。

单用协方差评分失败后，`rollout`/`flow_rollout` 对低成本筛选后的候选模拟最多三轮完整定位包：包括第一侧失收、另一侧往返、双陰性切割、后续定位和退出位置，而不是只奖励一次观测的外包收缩。假设粒子由当前外包的面积求积、实际成功接收锚点允许的朝向及±1°误差端点生成；全部仅用于排序，从未赋值给真实外包、未代替真实RF。

`flow_rollout` 进一步在认证清除可行域内最小化“当前位置→清除落点→后继任务”的距离。优化器返回点必须经全部外包顶点的20 m包含检查，失败则保留原可行点。原35 m试探门槛及实际20 m成功判据都没改。

### C. 两侧承担不同任务的非对称探测对

`asymmetric` 在 `flow_rollout` 基础上，加入“第一侧保留较宽基线用于定位；第一侧失收后，第二侧贴近满足排除证书的窄侧”的候选，也允许比较反向执行顺序。仍用完整定位预测选择，实际反馈决定是否执行第二点。它不保证每次都选择非对称点。

这一变化依靠一个几何事实：原双阴性证书不要求两侧对称。令成功锚点为原点，观测方向为x轴，真实源满足 `x≥0, |y|≤tx`，其中 `t=tan(1.02°)`。两点取 `q+=(l,k+ l)`、`q−=(l,−k− l)`，每侧均满足 `t≤k±≤tan30°`。对 `x≥l`，分别有

```
||q±−g||² − ||anchor−g||² ≤ l²(k±² − 1 + 2k±t) < 0.
```

因此两点都不比已接收锚点更远；两点连线又跨过源到锚点射线在 `x=l` 的截点，任何包含锚点的接收半平面至少包含一侧。**只有两侧实际都失收才可保留 `x≤l`。** 同样论证适用于复用的真实历史锚点。这里改变的是探测位置，测角误差仍严格为±1.01°。

## 3. 训练、冻结与独立验证

探索阶段反复使用相同的105个训练场景 `20260914000—20260914104`，不将重复执行算成独立场景。其基线为457.328 s/源，阶段结果如下；数值只用于开发判断。

|---|---:|---:|

|`ready`|+43.731|105/105|
|`history_window`|-2.597|105/105|
|`corridor`|+12.723|105/105|

**否决及原因：** `ready` 显著变慢，说明少做补测会错过附近清除时机，形成后段专程清理；`corridor` 的协方差评分低估了定向失收与后续往返；`window`/`history_window` 约2.6 s/源的训练小收益区间跨零，不能作为推进路线已解决折返的证据。全局预测也没有稳定优于单源完整定位预测。

最后用210个训练场景 `20260914000—20260914209` 完整覆盖配方，基线467.942 s/源。在 [freeze.json](freeze.json) 中预先指定 `flow_rollout` 为主验证候选，`asymmetric`、`flow_forecast`、`history` 为辅助候选，随后冻结。验证种子为全新的 **20260920000—20260920419**；没有用验证成绩继续改策略。

每210局由7个源数（10—16）×3种位置（uniform/edge/clustered）×5种误差（iid、smooth、恒+1°、恒−1°、空间±1°）×2种半径/朝向配方组成。配方分别为均匀半径/均匀朝向与固定1000 m/朝外；定向比例设为0.5。验证420局重复此组合两遍，使用独立种子，每候选共5460源。误差为固定的位置/频道/种子函数，不因改变调用顺序而重新抽样。这是明确的本地合成分布，不代表官方场分布。

统一估计 `τ=Σ整局虚拟秒/Σ真实源数`，不平均逐局τ。95%区间为4000次整局配对bootstrap。四候选同时比较的保守区间也保存在 [analysis.json](validation/analysis.json)：`asymmetric` 为[-5.370, -1.205] s/源，仍全为负值。其验证优于训练主选候选是事后排名，不能伪称它是训练最优。

## 5. 硬约束审计与适用范围

- 全流程共 **4431 次整局执行，4431/4431 全清**，其中包含训练反复与审计复跑；真正新生成的独立场景为210训练＋420验证。没有将4431次执行说成4431个独立场景。
- [public_audit.py](public_audit.py) 只记录公开观测、保留外包、实际探测对及清除点；策略代码不导入mock，不读真实源、种子或误差场。真值只由整局结束后的 [verify.py](verify.py) 使用，结果不会返回策略。
- 验证审计检查 **211309 个外包状态**均包含该频道真实源；检查 **28993 个返回探测对**的真实成功锚点、同一纵向截面、异侧及各侧1.02°—30°斜率。计数包括规划过程中返回但未实际执行的合法候选对。
- **21761 次认证清除**均通过证据核查：21669 次来自全部外包顶点的20 m包含，92 次来自真实 near 响应；0认证清除失败、0外包丢真值、0探测对几何失败。[完整审计](validation/geometry-verification.json)。原35 m试探不冒充20 m认证。
- 原21站坐标、任意朝向覆盖使用方式、少于16源时未知频道逐站RF、公知16源停机规则均未改；原有限光学兜底、每源10轮/20次主RF与全局16次中断预算保留。继承代码的最终断言全部通过。
- 21次带审计复跑与训练对应运行的虚拟时间精确一致；所有验证账本与按实际坐标重算的累计时间残差不超过 7.18e-06 s，属于逐段微秒舍入。[完整性结果](integrity.json) 记录生产与冻结快照哈希均未变化。

候选扩大了锚点/行进相关位置选择，**不能直接沿用旧证明中每段1900 m的内部移动界及其整局最坏时间结论**。本轮维持的是几何安全、有限兜底和这些mock局的实测全清；没有触发正式测试或宣称新的正式最坏时间保证。三轮预测仍使用简化位置/朝向/后续测量先验，未精确预测未来新源发现和跨源共享；这是均值小改善却仍有尾部回退的主要模型限制。
