# HTTP 客户端健壮性修复

仅修改 `client.py` 的内部实现。`Client` 构造参数及 `enter()`、
`measure(position, channel)`、`clear(position, channel)`、`exit()` 均保持不变。
原有二参数本地 transport 继续可用。`HttpTransport` 增加可选的内部关键字参数
`deadline`、`transcript`；原有二参数调用方式继续可用。

- 响应截断、损坏 JSON/UTF-8、连接重置与超时进入有限幂等重试。
  请求只序列化一次，重试保持路径、ID、字节一致。完整 HTTP 错误响应仍直接拒绝。
- 每个 Client 使用 UUID 前缀，避免同会话重建后命中旧 `/enter` 缓存。
- 使用 `/enter` 调用开始时间加服务端 remaining 得到保守绝对截止时间。
  普通动作提前 2 秒截止，显式退出提前 1 秒截止，分别预留退出与落盘时间。
  每次连接及分块读取限制剩余 timeout；退避后不足时间不再重试。
  这是网络等待预算，不能保证操作系统调度或磁盘写入具有硬实时上界。
- 重试耗尽后禁止该 Client 发送新动作；不自动调用 `/exit` 查询关闭原因。
  已知达到虚拟期限、已成功退出或现实预算耗尽也不发送事后查询。
- 频道在本地检查为 1..20 的整数值；接受 `1.0`、NumPy 整数，拒绝
  `1.5`、布尔、字符串、非有限值与越界值。

失败尝试通过现有 `transcript.append` 写入 `event=transport_failure` 行，
含尝试次数、请求、状态、异常，以及 Base64 编码的原始请求和已收到响应片段。
现有 JSONL Journal 可直接落盘；无 Journal 时可检查 transport 的 `failures`
（最近一次调用的失败尝试）。完整响应的原有日志结构不变。

## 会话恢复边界与独立设计

本修复不新增恢复入口。新建 Client 后重新 `/enter` 不是恢复方式：
对仍在进行的同一会话，应收到服务端拒绝，不能拿历史入场响应重置本地状态。

未来若实现恢复，必须独立持久化会话身份、前缀/序号、最后确认的位置/频道/虚拟时间、
原始截止信息及未确认动作的路径/完整字节。恢复时先校验仍为同一会话及剩余预算，
仅重放未确认动作的原字节、原 ID；收到完整响应后更新状态，再允许新动作。
跨进程重启不得直接沿用未校验的 monotonic 值，也不得重新 `/enter` 推断状态。
无法确认会话、截止或 pending 动作时停止，由用户处理。

## 本地回归验证

在 B/ 目录运行（只读使用已有 NumPy 环境，不修改 models/q1q2）：

```sh
../models/q1q2/.venv/bin/python -m unittest discover -s tests -p test_client.py -v
```

故障注入使用替代的 `urlopen` 与 `simulator.Protocol`，验证服务端动作已执行后
丢失响应的幂等行为。真实 HTTP 冒烟测试只连接测试自行创建的
`127.0.0.1` 临时端口，退出后关闭服务；不连接默认端口、官方模拟器或正式测试。
