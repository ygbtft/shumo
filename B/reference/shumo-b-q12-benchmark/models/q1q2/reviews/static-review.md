## 阻断级问题(必须改)

### **B1 — 返回的“保守覆盖圆”圆心与半径不配套，可漏掉合法源**

- **位置：`diagnostics.py:69`、`diagnostics.py:74`、`diagnostics.py:76`；下游 `run.py:135`。**
- `r_upper` 是以外包最小圆心 `center=c.center` 为中心、覆盖全部 U 顶点的半径；进入 direction 的 `ON_SITE` 分支却把 `cover_center` 换成 `q`，仍返回同一个 `r_upper`。因此 `(cover_center,r_U)` 不再是一个有包含依据的圆。`run.py` 正好把这个错误组合画成“保守覆盖圆”。违反 PLAN §7.9 的 `c_U/r_U` 配对合同。
- 静态反例可直接取现有 `tests/test_q2.py:220` 构型：目标圆中心 `(1000,0)`、半径 1，首站 `(0,0)`、读数 0°，第二站 `q=(1000,12)`、读数 270°。源 `(1000,0)` 合法且距 q 为 12；U 是目标小圆的切线外包再经角锥裁剪，最小覆盖半径至多约 `sec(π/32)<1.005`，但代码输出中心 q、半径约 1 的“保守圆”，显然不包含该源。
- `ON_SITE` 状态本身由 `H_U<20` 支持，**错误是输出的覆盖证据及图件，不是该例原地清除结论**。必须保证返回中心与半径对应，或把原地行动位置和外包覆盖圆心分成明确字段。补测返回圆包含全部 U 顶点以及独立合法后验点，不能只断言状态和 `H_U<20`。

### **B2 — F 为空时，命令入口在保存异常状态前崩溃**

- **位置：`run.py:226`、`run.py:229`、`run.py:147`、`run.py:151`、`run.py:275`。**

### **B3 — 预算曲线换了评分，却保留旧反馈、旧稳定性和旧比较结论**

- **位置：`q2.py:784`、`q2.py:791`、`q2.py:805` 至 `q2.py:815`。**
- `movement_frontier` 重新建立公共样本并产生新 `Score`，最后用 `replace(old, ...)` 更新 `q_best/score`。只以“坐标是否相同”决定保留清除诊断和变化范围，遗漏了**同一 q 的样本、见证和代表反馈已经变化**的情况。相同坐标不意味着旧条件 R 对应新 `score.witness.common_bearing_deg`，也不意味着旧范围覆盖新评分。
- 换了 q 时虽清空部分字段，仍保留 `station_change_m`、`stability`、`improvement_status`、`tie_threshold_m` 和旧 `alternatives`；实际本轮 tie 是第 794 行的共享值。可出现“当前 score/q + 旧推荐点的稳定标签、改善结论、备选排名”的混合结果。新选点的条件 R/清除诊断还会直接消失，未给未计算原因。

### **B4 — 大幅错位采样变化仍可标为“细化稳定”，外层变化还漏掉局部解**

- **位置：`q2.py:493` 至 `q2.py:503`、`q2.py:687` 至 `q2.py:703`、`q2.py:710`。**
- `STABLE_UNDER_REFINEMENT` 只看最后两级基础样本差和 `tolerance_change_m`。独立错位采样发现的提升、公共补点后的提升、局部点对精化增量均未进入稳定性门槛；它们只进入 `sensitivity_range_m`。若所有候选在错位采样后都上升很多、排名不变，就不会触发 `rank_flip`，仍可能输出“稳定”。这正是 PLAN §7.5/§11 所防范的共同漏采情形。
- 可按字段直接推导：基础三级分数全为 10、容差对照也为 10，错位/最终公共分数为 100，且各候选排名保持不变；代码仍满足第 500 行门槛并输出稳定，尽管自身已保存 `(10,100)` 的变化范围。这是分支逻辑反例，不声称本次实际运行得到这些数值。
- `station_change_m` 只比较两次规则网格赢家，没有把局部细化赢家纳入。两级网格赢家相同而局部解显著改善时，该字段可为 0，违反 §7.5“50/25 米扫描与局部细化统一重评”的口径。
- 必须让稳定性依据包含实际完成的独立审计及最终重评变化，并明确哪些比较未完成；外层变化需覆盖文档指定的三个阶段。变化范围本身未被写成严格误差上界，这是正确的，但不能据不完整子集误标稳定。

### **B5 — S4 行动域消融的旧 q 合法性检查漏掉 q∈A**

- **位置：`diagnostics.py:231`；`run.py:252` 至 `run.py:259`。**
- S4 用 `restrict_action_to_arena=True` 限制新搜索，但旧 q 的 `old_check` 仅调用 `check_candidate`，它检查的是原始 Q 和 C_sig/C_dir，不检查新加的目标圆行动限制。旧 q 在 A 外且仍保收时，被记录为 IN 并正常评分；新 q 却必须在 A 内。于是“旧 q 是否仍可行”的结论直接错误，且比较双方约束不同。
- 必须对旧点应用该实验的全部行动约束，再决定是否评分，并区分“仍保收”与“满足消融行动域”。PLAN §11.6 明确要求改变行动域后先判旧 q 可行性；域外站点恰是 S4 重点。

## 建议改进

1. **公开评分/后验 API 应明确并防守保收前提。** `q2.py:290` 只检查源样本属于 F，`q2.py:248` 选择 `rho=max(rho_lo,r1)` 后不检查第二站距离≤rho，却在 `q2.py:257` 无条件标 `actual_legal=True`。例如默认 F、q=`(3000,0)`、唯一样本 `(1000,0)`：返回的最小半径世界 rho=1000 在第二站距源 2000，实际为 no_signal，不能是合法 direction 世界。主搜索一般通过候选检查避免此输入，但公开 API 和 BOUNDARY 未决结果仍应有前提声明/状态校验。`feasible.py:363` 的后验简式与 `feasible.py:380` 的外包也依赖 §6.1 的 q∈C_sig；域外调用时前者省略接收约束而后者增加接收圆，不再彼此对应。

2. **不可实现反馈应区别于合法 near 的解析保证。** `diagnostics.py:47` 无条件返回 near 的 `ON_SITE`，不检查 F 状态或反馈是否可能。没有样本当然不应阻止合法 near 的解析保证，但 q=S 时 near 明确不可能（`feasible.py:367`）；这种矛盾输入应报告保证失配/不一致，而不返回一个可执行状态。可在 API 中明确“已接受且可实现反馈”前提，避免把空后验当清除成功证据。

3. **源边界构造应保留数值未决，不把所有采样失败解释为物理矛盾。** `feasible.py:95`、`feasible.py:175`、`feasible.py:179`、`feasible.py:190` 采用直接零比较或固定 `1e-8`，与传入 NumericPolicy 不一致；`feasible.py:277` 在不能构造实际点时总返回 `INCONSISTENT_FIRST_OBSERVATION`。近切、极窄角域、零宽非轴向射线可能受角度反算和判别式消减影响；需要独立残差复查后区分已证空与数值未决。本项为静态风险，未宣称已构造并运行某个失败浮点输入。

4. **边界元数据应描述端点开闭及实际距离。** `feasible.py:246` 的 wedge 线段始终 `attained=True`，即使端点落在被排除的 5 米圆；`feasible.py:227` 的其它圆弧也只按来源标签决定 attained。当前见证会再用 `contains` 核对，因此未直接发现主评分使用非法 5 米点，但暴露的 BoundaryPiece 元数据不准确。另外 `feasible.py:326` 给所有 q=S 返回 `distance_to_closure=near_radius`，而裁剪后的 F 可能离 S 至少 100 米；S∈C_dir 的结论正确，这个数值字段不一定正确。

5. **自定义网格仍应保证全部样本嵌套。** `q2.py:150` 保留了旧极坐标网格，但 `q2.py:172` 的圆弧/线段边界采样仅使用当前级 `grids[level][0]`。默认 9/17/33 是嵌套的，允许的自定义网格却未要求此性质（`q2.py:52`）；裁剪目标圆的弧参数与源极角不是同一参数，旧边界点不能靠旧极坐标循环保证保留。应并入旧边界样本，或拒绝不满足嵌套合同的配置。

6. **数值/配置状态校验补齐。** `q2.py:54` 的 tie 参数只检查负值，不拒绝 NaN/Infinity；站点步长数量/顺序与网格计数整数性也未完整验证。`diagnostics.py:168` 对空 `steps_m` 会索引空列表，非有限步长未拒绝；零维/一维后验面积已知为 0 时仍可能标分辨率不足。应让不支持配置在入口产生明确错误。

7. **缩小主搜索的耦合与重复工作。** `q2.py:444` 至 `q2.py:772` 把扫描、重评、救援、结果装配和诊断放在一个大函数内；`q2.py:506` 懒导入 diagnostics，后者又在 `diagnostics.py:12` 导入 q2 类型。当前未见必然循环导入错误，但这使结果一致性难以检查。`q1.py:45` 和 `circle.py:155` 对同一顶点集重复计算最小圆；`q2.py:719` 的粗级重评不计 evaluations。建议整理职责及统计，而非扩展更多数学求解器。

8. **清理无效变量，避免误导性注释。** `q2.py:320` 的 `valid` 只被用于数组 shape，真正筛选用 `band` 加原始角度复核；可以明确这条路径。`feasible.py:3` 的 field、`diagnostics.py:4` 的 combinations、`diagnostics.py:9` 的 clearance_diameter_regime、`run.py:4` 的 asdict 等未使用。多数注释是必要数学语义，未见大量废话，清理应集中在这些实际冗余。

## 与PLAN偏差

1. **S7 的“几何容差×0.1/×10”没有贯穿候选与后验链路。** `q2.py:695` 创建新 policy 只放入 SearchConfig；`_sample_sources` 仍使用旧 ss.policy，`closure_distance` 也用旧 SourceSet，终选 q 没有在变化后的边界构造/候选判据下重验。`feasible.py:363` 的 policy 参数本身未使用。故 `tolerance_change_m` 实际主要反映评分阈值探索和 near 偏移，不能代表 PLAN §7.5/§11.6 要求的全链路容差敏感性。

2. **三种误差模式在公开观测路径正确分开，手工 JSON 路径未保持同一合同。** `adapters.py:125` 仅拒绝 `OFFICIAL_UNKNOWN`，不校验其余 error_mode 枚举值与 half_width、rounding_mode、来源是否一致。标记 `NEAREST_ROUNDING_OUTER_1_005_DEG` 但省略 half_width 的 JSON 会得到默认 1°；反向也可标理论 1° 却带任意半宽。这不妨碍手工数学实验使用自定义半宽，但结果不应冒用一个含精确定义的模式名。`run.py:224` 只要存在任何配置文件就不再跟随首测半宽，即使文件只设置物理参数；至少应保存并清楚说明显式/默认第二半宽来源。

3. **完整验证方案尚未实现。** `diagnostics.py:222` 只生成一个输入上的 S1/S3/S4 变体；`run.py:250` 才显式启动它们，缺少 S1 跨零/普通/近切三例、S3 标准与目标边缘对照、S4 确实出现域外损失的固定案例以及 S7 的 tie=0/0.5/1/2 对照。S2 基础逻辑和反例测试已具备，S7 部分数值审计已写，但不能称 S1/S2/S3/S4/S7 完整交付。开关延迟昂贵实验是合理工程安排，不能据此删除必做验收。

4. **预算值 V(B) 和“必须不同站点”的结果合同混用。** `q2.py:780` 调用排除 S 的 `_search`，B=0 得 `NO_DISTINCT_CANDIDATE`；`run.py:244` 又把 baseline 分数画为 V(0)。PLAN §6.4 的 V(B) 包含 S，§6.5 则要求不同第二点单列。数学上 baseline 正是 V(0)，但当前 JSON 的 score/q_best 与图中的预算值口径不同，应显式提供预算值及基线选项，保留“没有不同站点”的独立说明。F9 也没有传入 low/high 变化带和清除状态（`run.py:244`），未完成 §12 的并列展示。

5. **F7 会把不属于当前反馈的点对画在 K 中。** `run.py:139` 对每一条清除诊断都画全局 `result.score.witness`。若全局最坏反馈为 direction 而另画 near，或相反，该对不能共同产生图面当前反馈；也没有用 `posterior_contains` 检查这条线。图中的 K 样本、R_hat 和点对会表达不同条件。应按反馈挑选/复核见证，否则不画。`run.py:105` 还用默认 source_grids 重新生成展示样本，未复用实际配置与终选公共补点；其样本圆与散点可能不对应，削弱可复现解释。

## 测试缺口

1. **五个阻断问题缺少针对性回归。** `tests/test_q2.py:220` 没有验证 ON_SITE 返回圆；`tests/test_feasible.py:79` 未覆盖空 F 的 run/bundle 导出；`tests/test_q2.py:238` 只测小搜索，全部测试没有调用 movement_frontier；没有构造错位变化大但排名不变的稳定性分支，也没有检查 S4 旧点被新增行动约束排除。应优先补这些真实失效路径。

2. **连续夹具的评分 oracle 独立，但尚未验证采样器/细化器能发现解析极值。** `tests/test_q2.py:89` 把闭式内端点 `inner+1e-9` 直接加入样本；这能验证有限点对评分、发现只算几何端点的错误，不能验证 `sample_sources + refine_pairs` 找到内端点。`tests/test_q2.py:104` 同样手工放入 95/105 两侧端点，未测自动 near 补点与逼近。需要分别保留这两类测试，不能把当前手工 oracle 注入称为端到端连续求解验证。

3. **一般圆弧事件/裁剪候选缺独立解析 oracle。** `tests/test_feasible.py:22`、`:36` 的四盘 oracle 对标准场景有力；`:79` 的域外例仅检查 F 状态、S∈候选和样本不越目标圆，没有核验裁剪场景的 g_L/g_H 极值、弧内驻点和候选边界。`:99` 仅验证一个轴向相切单点，没有接着检查其 C_sig 圆盘与 C_dir 的 5 米等号。应补已知单点/线段 F、圆弧消失、目标圆切点、分界 r=rho_lo 和非轴向相切例。
