# Q4最近邻与参数融合候选

推荐新候选：最近邻任务排序、35米试清门限、fraction=0.30、share_limit=2。其余参数采用原默认：share_cooldown=150米、transverse_m=40米、steps=10、pause_limit=16；覆盖布局grid21_29，距离删测、负反馈裁剪、共享补测与光学兜底保留。20米物理清除距离不变。

## 依据

全部来自2026-09-13官方演练原始记录，主时间指标为逐局平均定位清除时间的算术平均。

|实验批次|设置|局数|平均定位清除时间/秒|相对同批baseline|
|---|---|---:|---:|---:|
|消融|完整策略，35米|10|509.25|0.00%|
|消融|最近邻任务排序，35米|10|463.81|-8.92%|
|参数宽扫|完整策略，默认参数|10|451.31|0.00%|
|参数宽扫|仅fraction改为0.30|10|437.91|-2.97%|
|参数宽扫|仅share_limit改为2|10|440.22|-2.46%|

fraction控制沿当前可行区域投影区间的探测位置，length=low+fraction*(high-low)；0.30比原0.15更靠前。share_limit=2把单次顺路补测的最多已知源数从6降为2。它们与dispatch='nearest'分别作用于探点、补测和任务排序，在当前Q4代码路径均可生效。

参数宽扫中其余参数的非默认档位均未出现比同期baseline更低的算术平均定位清除时间，因此没有一并替换。steps=1的10局累计39次任务兜底、401次清除失手；steps=3也累计6次任务兜底，因此保留10轮预算。

fraction=0.30组累计0次清除失手、0次兜底，share_limit=2组累计2次失手、0次兜底；两组各10局全清。这是已测案例记录，不是融合后的保证。参数实验的客户端程序耗时均值分别比该批baseline高4.15%和10.58%，候选选择依据是任务的平均定位清除时间，而非程序耗时同时改善。

消融与敏感性使用的原始策略核心文件一致，已核对冻结快照；两批案例不同，baseline从509.25变为451.31本身说明批次波动明显。不能把-8.92%、-2.97%、-2.46%相加作为融合后预测。每档只有10局，单因素筛选存在偶然排名和参数交互；预设联合扰动实验也没有通过5%非劣效判据，不支持任意组合均稳健。

## 推荐的新实验

使用官方演练，三个配置各10局，总计30局；10个执行区组，每个区组随机顺序运行各配置一次。官方每局都是新案例，区组仅平衡时间顺序，不是同案例配对。

|配置|任务排序|试清门限/米|fraction|share_limit|用途|
|---|---|---:|---:|---:|---|
|nearest35|最近邻|35|0.15|6|新批次对照|
|nearest35_fraction30|最近邻|35|0.30|6|观察fraction与最近邻组合|
|nearest35_fraction30_share2|最近邻|35|0.30|2|推荐融合候选，观察限制补测的额外影响|

主比较为融合候选对同期nearest35。逐局记录清除数、平均定位清除时间、程序运行时间，三个指标分别相加除以10；两个时间均值报告相对同期nearest35的偏移。程序运行时间统一使用官方/exit与/enter响应时间戳之差，客户端wall_s仅另存辅助。共同检查每局是否全清、失手数和兜底数；未全清不能按短时间判为改进。

配置在新数据产生前固定，全部案例保留，不按中途成绩删局或重抽。若30局未完成则明确报告实际数量；小样本结论限定为新案例上的探索性比较。
